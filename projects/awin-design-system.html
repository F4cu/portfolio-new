Awin Design System

Building a scalable, token-based design system for a global B2B SaaS platform, aligning design and engineering while supporting complex, data-heavy interfaces.

Role

Senior UX/UI Designer (IC)

Main Goal

New scalable foundation

Challenge

An increasingly fragmented platform

Awin's growth from 2 to 10+ dev teams triggered a UI breaking point. Without a unified system, squads operated in silos, leading to exponential technical debt. Design shifted from "reusable" to "repeated," with teams constantly recreating components from scratch.

The platform hosted five different date-pickers, each with unique behaviors and accessibility gaps. Maintenance became a "consistency tax", rebranding required manual fixes across hundreds of instances instead of a simple token swap.

Aproach

From UI audit to scalable design foundations

1. Comprenhensive Interface Audit

I began with a comprehensive audit of key dashboards and reports, cross-referencing behavioral analytics (Amplitude and Hotjar) with heuristic evaluations and Lighthouse audits. This data-driven approach moved the conversation beyond visual critique, allowing us to pinpoint high-impact usability gaps and user friction where it mattered most in real-world usage.

2. Strategic Scoping and Phased Rollout

To define the scope, I mapped the platform via a component-to-page matrix to identify high-frequency elements and critical inconsistencies. This data informed a phased release strategy, where I used a prioritization framework to select an initial pilot with high component coverage but low technical risk. By excluding complex dashboards from the first build and instead using high-fidelity mockups to align stakeholders on the vision, I was able to validate the system in a controlled environment while maintaining a predictable, scalable rollout.

3. Foundation Research

I conducted a deep-dive into competitor benchmarks and industry best practices to reengineer the component architecture for long-term scalability. I developed a system optimized for the unique constraints of data-heavy interfaces. This process involved stress-testing color palettes and layouts against real-world density requirements, ensuring that the new foundations provided the performance and visual clarity necessary for complex user workflows.

  • Atomic Framework: A scalable UI pattern structure based on Atomic Design principles.
  • Rebuilt Color System: Full WCAG AA compliance with dedicated support for data visualization.
  • 8pt Spacing System: Semantic roles featuring multiple density levels for complex layouts.
  • Open-Source Typography: Optimized for legibility and performance while eliminating licensing overhead.
Solution

What changed

Accessible, Token-Based Architecture

The result was a scalable, token-based design system that elevated the platform to WCAG AA compliance by embedding accessibility into its core. By standardizing components and interaction patterns, the system established a common language between design and engineering, significantly reducing duplication across complex, data-heavy interfaces.

Documentation Driving Team Efficiency

The design system guidelines were structured using Atomic Design principles, organizing components into Foundations, Atoms, Molecules, and Organisms to create reusable, scalable building blocks. Beyond component anatomy, the guidelines also defined interaction behavior, responsive rules, accessibility, spacing, and content standards to simplify hand-off between design and engineering.

See documentation examples: Typography | Color | Input

Quality through Agile Governance

I introduced a hybrid governance model where a small central group maintained core foundations, while feature teams contributed localized patterns and extensions. To prevent bloat, new shared components followed a “3 uses” heuristic, requiring adoption across multiple features or teams before entering the core library. This balanced consistency, scalability, and team autonomy.

Impact

Beyond the Baseline

The system transformed the platform into a centralized design API. By abstracting brand logic into tokens, we enabled global-scale updates that can be deployed instantly, rather than component-by-component. Beyond lowering licensing overhead with open-source typography, we prioritized functional legibility to reduce user error in dense data environments. This common language has effectively eliminated the "design-to-code" gap, allowing engineering to focus on core product logic while the system handles the complexities of accessibility, responsiveness, and visual consistency.
